# Personalized MemoryCast narration

New tours use high-detail OpenAI photo understanding, an evidence-linked three-chapter script followed by an evidence-edit pass, and `gpt-4o-mini-tts` with the Coral voice. Script generation defaults to `gpt-4.1-mini` (server override: `MEMORYCAST_SCRIPT_MODEL`), because a larger draft model did not answer inside the script budget and every tour became a verbatim reading. Set server-only `MEMORYCAST_SCRIPT_PROVIDER=deepseek` to use the existing Lablup client instead. No provider fallback or paid retry happens automatically.

The writer uses the saved title and journal text as the spine and visible photo details to move through the memory. It must distinguish visible observations from personal history and only attribute emotions supplied by the writer. The script plan selects known source IDs and the server attaches their text; the server also attaches the saved entry and one photograph to the chapters that require them, and repairs a paraphrased reading quote to a real sentence, so a model draft is not discarded over auditable metadata. A journal interpretation must cite the written entry. Both writing and editing use the selected script provider, with an 18-second draft, an 18-second repair only after a rejected output, and a 12-second edit inside a 40-second script step; provider errors and timeouts are never repeated. If the draft still fails — rejected output, provider error, timeout, or a writer running past the step budget — the script step still completes with a cost-free verbatim reading of the saved story (or photo analysis). That fallback only ever speaks saved text, skips notes-to-self and stubs, and keeps each chapter specific to that memory, so two memories never share a recording. Exact evidence references are validated; this validates references, not the factual accuracy of every generated sentence. Subjective quality still requires review.

The version-5 fingerprint marks every recording made by the previous narration engine as stale, so the player offers an explicit **Update narration** action instead of silently replaying it. Replaying uses saved audio and never generates again; updating reserves a new tour and uses the narration allowance and provider billing. Existing RPCs and private audio storage are unchanged; no migration is required. World Labs world generation and its three-per-account allowance are unaffected.

A technical or sparse journal entry cannot support a rich personal narrative. The script should focus on visible details rather than invent relationships, events or feelings. Missing spatial anchors never become inferred camera coordinates.

Older generic recordings are hidden by default and can only be replayed through an explicitly labelled previous-recording action. A failed obsolete version can be explicitly updated; uncertain billing states still require owner review. No automatic paid retries are introduced.

Narrative priority: journal experience and supported feelings first, photo observations second, saved symbolic scene visualization third. Scene title/environment/mood/object types are passed as interpretation-only context, not personal evidence. Missing plans remain absent; podcast generation does not generate a new DeepSeek scene or World Labs world. The writer and editor preserve a calm personal reflection rather than an object inventory. Speech uses warm, soft podcast pacing.
